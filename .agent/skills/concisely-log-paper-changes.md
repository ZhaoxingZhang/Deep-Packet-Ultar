# 简洁总结论文改动

描述：将论文或代码改动简洁地总结并追加到研究日志文件末尾

## 何时使用

当完成论文修改、代码重构等重要工作后，需要记录到研究日志时使用。

## 输入参数

- `changes`: 改动内容描述（数组，每个元素是一个改动点）
  - 每个改动包含：位置、改动前、改动后（可选）
  - 格式：简洁描述，一句话说清楚

- `date`: 日期（可选，默认使用当前日期格式：2026年3月7日）

## 输出格式

```
## 日期：{date}

### {工作主题}

{改动列表，格式：**序号. 改动说明** (位置)
- 简洁描述改动前
- 简洁描述改动后
```

## 格式要求

1. **简洁为主**：每个改动点1-2行，不超过3行
2. **只记改什么**：记录改动内容，不记录实施方式
3. **不包含**：
   - Git commits、命令行操作
   - OpenSpec artifacts、文件路径
   - 实施步骤、调试过程
   - 实验结果、性能数据（除非是改动目标）
4. **技术细节优先**：明确位置（行号、章节、函数名）
5. **对比清晰**：改动前后用箭头或引号标注

## 示例

**输入**：
```python
changes = [
    {
        "location": "Line 31",
        "before": "提到加密技术但没解释原理",
        "after": "添加加密原理：明文→密文，载荷不可见，DPI失效"
    },
    {
        "location": "Line 43",
        "before": "提出了加权CE损失",
        "after": "修正为：创新性地应用加权CE到门控网络"
    }
]
```

**输出**：
```
## 日期：2026年3月7日

### 论文第一章系统性改进

**1. 添加技术背景** (Line 31)
- 提到加密技术但没解释原理
- 添加加密原理：明文→密文，载荷不可见，DPI失效

**2. 修正创新归属** (Line 43)
- "提出了加权CE损失"
- 修正为："创新性地应用加权CE到门控网络"
```

## 执行步骤

1. 读取研究日志文件末尾30-50行，确认格式
2. 根据输入参数格式化改动内容
3. 追加到研究日志文件末尾
