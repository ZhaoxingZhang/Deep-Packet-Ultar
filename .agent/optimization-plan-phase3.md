# 阶段三：实验验证与鲁棒性增强（优先级：中高）

## 3.1 补充OSR评测维度

### 目标
通过更全面的指标和统计检验，增强实验结论的说服力。

### 具体任务

#### 3.1.1 核心指标扩展
当前指标：FPR@TPR95, AUROC
需要补充：

1. **OSCR (Open-Set Classification Rate)**
   - 定义：在固定误报率下的开放集分类准确率
   - 优势：同时考虑分类准确性和未知类检测能力
   - 实施方案：参考Bendale & Boult, "Towards Open Set Deep Networks" (CVPR 2016)

2. **AUPR (Area Under Precision-Recall Curve)**
   - 重要性：对类别不均衡场景更敏感
   - 优势：当未知类样本数远少于已知类时，AUPR比AUROC更能反映真实性能
   - 实施方案：使用sklearn.metrics.average_precision_score

3. **校准误差 (ECE - Expected Calibration Error)**
   - 定义：
     $$ \text{ECE} = \sum_{m=1}^M \frac{|B_m|}{n} |\text{acc}(B_m) - \text{conf}(B_m)| $$
     其中 $B_m$ 是将样本按置信度分桶后的第 $m$ 个桶
   - 目的：量化模型置信度的可靠性
   - 预期：GEE应具有更低的ECE（更好的校准性）

4. **负对数似然 (NLL - Negative Log-Likelihood)**
   - 定义：$-\log P(y|x)$
   - 目的：评估概率预测的准确性
   - 预期：GEE在已知类上应保持较低的NLL

#### 3.1.2 统计显著性检验
当前问题：缺乏统计检验，无法确认"GEE的未知样本熵更高"是否显著

实施方案：
1. **Kolmogorov-Smirnov (K-S)检验**
   - 零假设：GEE和Baseline的未知样本Softmax熵分布相同
   - 检验统计量：$D = \sup_x |F_{GEE}(x) - F_{Baseline}(x)|$
   - 报告内容：K-S统计量D值和p值
   - 预期：p < 0.05（拒绝零假设，证明分布显著不同）

2. **Bootstrap置信区间**
   - 对所有关键指标（FPR@TPR95, AUROC, OSCR等）计算95%置信区间
   - 方法：从测试集有放回抽样1000次，每次计算指标，取2.5%和97.5%分位数
   - 报告格式：指标值 ± [lower, upper]

3. **多次独立重复实验**
   - 在不同随机种子下重复5-10次实验
   - 报告均值和标准差：$85.3 \pm 2.1$%
   - 目的：验证结果的稳定性和可重复性

## 3.2 加强基线对比

### 目标
通过与更多SOTA方法对比，证明GEE的竞争力。

### 具体任务

#### 3.2.1 新增基线方法
当前基线：Softmax阈值（最弱）

建议添加：
1. **OpenMax** (Bendale & Boult, 2016)
   - 核心思想：使用极值理论拟合已知类logit的Weibull分布
   - 优势：经典OSR方法，广泛引用
   - 实施方案：使用开源实现（如openmax库）

2. **Energy-OOD** (Liu et al., 2020)
   - 核心思想：使用能量分数代替Softmax最大概率
   - 优势：理论基础扎实，性能优异
   - 实施方案：计算 $E(x) = -T \log \sum_j \exp(f_j(x)/T)$

3. **ODIN** (Liang et al., 2018)
   - 核心思想：输入预处理 + 温度缩放
   - 优势：简单但有效的后处理方法
   - 实施方案：对输入添加小扰动 $\tilde{x} = x - \epsilon \cdot \text{sign}(\nabla_x \log p(y|x))$

4. **LogitNorm** (Liu et al., 2022)
   - 核心思想：训练时对logit进行L2归一化，抑制过度自信
   - 优势：训练阶段修改，与GEE可互补
   - 实施方案：损失函数改为 $\ell(f(x)/\|f(x)\|, y)$

5. **Outlier Exposure (OE)** (Hendrycks et al., 2018)
   - 核心思想：使用辅助离群数据训练
   - 注意：需要构造合适的离群数据集
   - 可选：如果难以获取离群数据，可作为future work讨论

#### 3.2.2 对比实验设计
实验设置：
- 数据集：保持当前设置（USTC-TFC2016等）
- 已知类/未知类划分：使用多种划分方案验证鲁棒性
- 评估指标：统一的指标集（FPR@TPR95, AUROC, OSCR, AUPR）

报告格式：
| 方法       | FPR@TPR95↓ | AUROC↑ | OSCR↑ | AUPR↑ |
|------------|------------|--------|-------|-------|
| Softmax    | 0.47       | 0.82   | 0.75  | 0.68  |
| OpenMax    | 0.35       | 0.85   | 0.78  | 0.71  |
| Energy-OOD | 0.21       | 0.89   | 0.82  | 0.76  |
| ODIN       | 0.18       | 0.90   | 0.83  | 0.77  |
| **GEE**    | **0.03**   | **0.95**| **0.89**| **0.84**|

## 3.3 深入的消融实验

### 目标
分解GEE的两个核心组件（加权CE + 门控融合），量化各自的贡献。

### 具体任务

#### 3.3.1 组件分解实验
实验配置：
1. **Baseline (标准CE)**
2. **Baseline + 门控**（不使用加权CE）
3. **加权CE单模型**（不使用门控融合）
4. **GEE (加权CE + 门控)**

评估指标对比：
| 配置           | FPR@TPR95 | AUROC | 说明                       |
|----------------|-----------|-------|---------------------------|
| Baseline       | 0.47      | 0.82  | 原始基线                   |
| Baseline+门控  | 0.45      | 0.83  | 门控单独作用（应效果有限） |
| 加权CE单模型   | 0.12      | 0.91  | **加权CE的核心贡献**       |
| **GEE完整版**  | **0.03**  | **0.95**| 门控的额外提升           |

#### 3.3.2 门控机制分析
1. **可视化门控权重分布**
   - 绘制已知类样本的 $g_{baseline}(x)$ 直方图
   - 绘制未知类样本的 $g_{baseline}(x)$ 直方图
   - 预期：未知类更倾向于使用expert网络（$g_{expert}$更高）

2. **门控决策的熵分析**
   - 计算门控输出的熵：$H(g(x)) = -g_{baseline}\log g_{baseline} - g_{expert}\log g_{expert}$
   - 高熵表明门控"不确定"，可能更依赖expert

3. **对比其他融合策略**
   - 简单平均：$y = 0.5 \cdot y_{baseline} + 0.5 \cdot y_{expert}$
   - 最大值：$y_j = \max(y^{baseline}_j, y^{expert}_j)$
   - 验证学习式门控的优势

#### 3.3.3 权重策略消融
测试不同加权策略的影响：
1. **逆频率权重**：$w_j \propto 1/n_j$（当前方案）
2. **平方根权重**：$w_j \propto 1/\sqrt{n_j}$
3. **有效样本数权重**：$w_j \propto 1/(1 - \beta^{n_j})$（参考CBRF loss）
4. **无权重（标准CE）**

选择最优策略并说明理由。

## 3.4 跨数据集验证

### 目标
验证理论的普适性，避免单数据集过拟合。

### 具体任务
1. **多数据集实验**
   - 当前数据集：USTC-TFC2016
   - 新增数据集建议：
     - ISCX VPN-nonVPN（应用层流量）
     - CICIDS2017（包含DDoS等攻击）
     - 或其他公开的加密流量数据集

2. **不同不均衡比例**
   - 当前比例：假设为10:1
   - 新增比例：5:1, 20:1, 50:1
   - 绘制性能曲线：x轴=不均衡比例，y轴=FPR@TPR95

3. **不同已知/未知类划分**
   - Random split：随机选择部分类作为已知类
   - Hard split：选择语义上相似的类作为未知类（更具挑战性）
